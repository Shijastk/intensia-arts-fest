# Intensia Arts Fest — Code Audit (31 Oct 2026)

Replaces the outdated `codebase_audit.md`, which was written for the old Google Apps Script backend. No secret values are reproduced here.

## 1. Staff login issue — root cause and fix

**Symptom:** staff, judge and green-room logins fail with "Firebase Anonymous Authentication is disabled…" or "Invalid username or password." with correct credentials.

**Causes**

| # | Cause | Status |
|---|---|---|
| 1 | The Anonymous sign-in provider is off in the Firebase console, so `signInAnonymously` throws `auth/admin-restricted-operation`. | **You must turn it on:** Firebase Console → Authentication → Sign-in method → Add provider → Anonymous → Enable → Save. If Authentication → Settings → User actions → "Enable create (sign-up)" is off, turn it on as well. |
| 2 | `loginStaff` read the staff list *before* signing in. If the database rules require `auth != null`, every login would fail. | Fixed: the app now signs in first, then reads. |
| 3 | Credentials were compared with strict `===`. A username auto-capitalised by a phone keyboard (`Judge_123`), a password stored as a number, or stray spaces caused a false "Invalid username or password". | Fixed: values are trimmed and stringified before comparing, and the username match ignores case. |
| 4 | The login page loaded every fest's data, even on `/fests/:festId/login`. | Fixed: only that fest's `staff` node is read. |
| 5 | A disabled duplicate account could block an active account with the same credentials. | Fixed: disabled matches are skipped, and their message is shown only if no active account matches. |
| 6 | The anonymous-auth error was silently swallowed. | Fixed: the "enable Anonymous" message is shown only when the database actually rejects the request. |
| 7 | The username input auto-capitalised and auto-corrected on mobile. | Fixed: `autoCapitalize="none"`, `autoCorrect="off"`. |

Files changed: `src/services/authService.ts`, `src/pages/LoginPage.tsx`.

Still needed: database rules. The live database answers **unauthenticated reads of `/fests` (HTTP 200)**, so anyone can download every staff password. No `database.rules.json` is in the repo.

## 2. Findings

### Critical
1. **`.env` is committed to git** and `.gitignore` doesn't cover it. It contains the ImgBB API key, a real secret that also ships in the bundle (`src/services/imageUploadService.ts:2`). Fix: untrack the file, add `.env` to `.gitignore`, and rotate the key.
2. **`accounts.json` (a Firebase Auth export of 10 Google users) and `db_users.json` (a dump of `/users`) are committed.** Both contain personal data. Fix: delete them and purge them from git history.
3. **The Supreme Admin passkey is a plaintext literal** (`src/pages/SuperAdminPage.tsx:46`). Access is only a sessionStorage flag (`supreme_admin_auth=true`), which anyone can set by hand. Fix: Google sign-in plus a custom claim, enforced by the rules.
4. **All authorization is client-side.** `App.tsx:54-57` trusts the user stored in localStorage. Changing `role` or `festId` gives admin access to any fest (`DashboardLayout.tsx:113-156`).
5. **Hardcoded `admin` / `admin` login** (`App.tsx:90`) creates an admin session for any fest.
6. **Staff passwords are stored in plaintext and are publicly readable.** Every logged-in user also live-subscribes to the staff node (`useStaffs.ts:17`, `GreenRoomPage.tsx:97`). Unpublished scores are readable from `fests/*/programs`. Fix: write rules, hash passwords, and move login to a Cloud Function that issues custom tokens.

### High
7. The "Seed Defaults" button creates accounts with guessable passwords, including a staff account with role `ADMIN` (`AdminPage.tsx:550-555`).
8. **Lost updates.** Team leaders, green room and judges each overwrite the whole `teams` array from possibly stale state (`TeamLeaderPage.tsx:179-190`, `GreenRoomPage.tsx:185,215`, `JudgesPage.tsx:256`). Fix: `runTransaction`, or per-team paths.
9. **Write failures are ignored.** `updateProgram` returns false, but callers still show success (`TeamLeaderPage.tsx:193,218`). Read errors become "no programs" (`programService.ts:32`).
10. **Crash on empty arrays.** RTDB drops empty arrays, but `.teams` / `.participants` are used without `|| []` (`consolidationCalc.ts:38,49`, `JudgesPage.tsx:63-64`, `TeamLeaderPage.tsx:206-210`). The public Results page can crash.
11. **Ranking includes unscored or no-show entries** (`JudgesPage.tsx:171-187`), so a no-show can earn 3rd-place points.
12. **Re-scored results stay public.** Re-scoring a published program leaves `isResultPublished: true` (`JudgesPage.tsx:258`).

### Medium
13. Publish-order race: two simultaneous publishes can get the same `resultPublishedOrder` (`programService.ts:46-54`).
14. Code letters break past 26 entrants and can produce duplicates (`GreenRoomPage.tsx:131-175`).
15. The green-room staff listener resubscribes on every change because the effect depends on `[programs]` (`GreenRoomPage.tsx:93-113`).
16. The disabled-user auto-logout timer keeps resetting (`DashboardLayout.tsx:135-143`), and `setState` is called inside `useMemo` (`:101-104`).
17. `/fests/:festId/dashboard` ignores the festId in the URL (`App.tsx:182`).
18. Whole-tree reads of `/fests` and `/users` (admin-login path, `SuperAdminPage.tsx:71-78`, `supremeAdminBackup.ts:34`).
19. A fest id uses a 4-digit random suffix with `set()`, so a collision overwrites an existing fest (`authService.ts` `createFestForAdmin`).
20. The "Fix Missing Orders" admin tool is visible to green-room staff (`GreenRoomPage.tsx:286-300`).
21. `JSON.parse(savedUser)` has no try/catch (`App.tsx:73`).

### Low / build health
22. `tsconfig` has no `strict` and no `include`, so it type-checks `kandiyiltraders/`. `vite build` never runs `tsc`. There are 3 existing errors (`src/components/Hero.tsx:51`, plus 2 in `kandiyiltraders`).
23. Dead files: `utils/authUtils.ts`, `utils/championCalculator.ts`, `services/resultOrderService.ts`, `mockData.ts`, and several unused components and Marketing sections.
24. Duplicates:
    - The Firebase config is copied into `scripts/*.ts`.
    - `googleProvider` is defined twice.
    - `DEFAULT_SETTINGS` differs between `useSettings.ts` and `settingsService.ts`.
25. Very large files: `ProgramAccordion.tsx` (954 lines), `SettingsPage`, `ScheduleManager`, `AdminPage`, `JudgesPage`.
26. `scripts/injectFirebaseData.ts:175` and `scripts/migrateOrders.ts:56` write directly to production data.
27. Scores are keyed only by chest number (`JudgesPage.tsx:65`).

## 3. Recommended order
1. Enable Anonymous Auth (unblocks staff today).
2. Remove `.env`, `accounts.json` and `db_users.json` from git, then rotate the ImgBB key.
3. Remove the `admin`/`admin` backdoor and the Seed Defaults passwords.
4. Write RTDB rules: no public read of `staff`; writes only for authenticated users.
5. Move staff login and supreme-admin login to a Cloud Function with custom claims.
6. Fix data-integrity bugs 8–12.
